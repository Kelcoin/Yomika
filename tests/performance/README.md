# 前端交互性能优化（2026-10-24）

目标：减少点击、触摸滚动期间与输入争用主线程的重复布局计算，保持现有功能、手势规则、滚动恢复和视觉样式。

## 实测与保留的改动

| 瓶颈与测试场景 | 修改前 | 修改后 | 处理方式 |
| --- | --- | --- | --- |
| 60 张卡片底部信息、相同内容连续更新 10 次；真实 Chromium，5 个样本 | 120.1–147.7ms，中位数 122.8ms；每样本 3600 次文字宽度读取 | 4.6–5.8ms，中位数 4.9ms；宽度读取 0 次 | 按容器宽度和每段文字复用字号测量结果；观察器不随父级更新重建 |
| 后台保留页面挂载 60 张卡片、每卡 6 个标签；jsdom 调用计数 | 720 次 offsetWidth 读取 | 0 次 | 页面隐藏时暂停测量和 ResizeObserver；激活时在布局阶段重新测量 |
| 当前保留页面监听到外部面板的 120 次滚动事件；jsdom 调用计数 | 120 次 getClientRects 读取 | 0 次 | 先判断滚动来源是否属于当前页面，再读取布局 |

浏览器测量原始样本（ms）：

- 修改前：147.7、121.5、127.6、120.1、122.8。
- 修改后：5.1、4.6、4.9、5.8、4.7。
- 保存为可复用基准页后再次验证：5.2、5.5、5.7、5.8、7.3；文字宽度读取仍全为 0。

后台标签计数中的 720 包含测试 ResizeObserver 在 observe 时立即回调的一次测量；它证明可以消除的重复工作量，不代表浏览器必然具有相同调用时序。滚动过滤优化也只减少外部事件的布局读取，当前页面自己的滚动仍按原规则记录位置。

## 失效与功能保证

字号结果只在组件本次激活期间复用，宽度或文字变化即失效；字体首次加载完成强制重新测量。隐藏、重新显示及卸载会清理观察器，旧字体回调不能改动隐藏或已卸载的组件。最小字号、页数优先、标签分行、卡片缩放与进度条对齐规则保持原实现。

检查了按压反馈、长按菜单、横向滚动和边缘过滚的事件路径。本次没有调整长按阈值、惯性曲线或触摸事件的 passive 规则：这些变化缺少新的测量证据，还可能影响轴向判定与过滚功能。也没有增加生产遥测依赖或收集用户数据。

## 复测方法

运行浏览器专项基准：

```powershell
npx vite --config tests/performance/vite.config.ts --configLoader runner --host 127.0.0.1 --port 27790
```

浏览器打开 `http://127.0.0.1:27790/tests/performance/card-footer.html`，等待字体加载后点击“测量”。每次运行 7 轮、每轮连续同步更新 10 次，丢弃前两轮预热，比较剩余 5 轮的耗时与 reads。基准使用真实组件和项目样式，没有模拟浏览器尺寸；仅用于专项比较，不能代替整个应用的 INP。

回归预算及功能验证：

```powershell
npm run test -- tests/components/touch-performance-budget.test.tsx tests/components/archive-thumbnail-card.test.tsx tests/components/card-tag-rows.test.tsx tests/components/compact-library-scroll.test.tsx
npm run test
npm run build
```

新增预算覆盖：不变内容不重复量字、不重建观察器；文字/宽度/页面激活/字体加载正确触发测量；后台标签不测量；外部滚动不读取布局；本页面滚动位置仍能恢复。

验证结果：最初 172 个测试文件、1864 项测试全部通过；真机修复后 173 个测试文件、1865 项测试全部通过。`npm run typecheck` 与 `npm run build` 通过。构建仍提示 Tauri core 同时静态/动态导入的分块警告，本轮未修改该导入结构。

## 验证边界

最初优化时 ADB 无连接设备；用户随后连接设备，补充了下面的 Android 真机测试。仍无 iOS 数据，以下测试也不能代表所有设备、页面和档案规模，不能承诺“移动端已完全不卡”。没有修改后端、推理路径或下载行为。

## Android 真机补充

设备：型号 24091RPADC、Android 16、1600×2560、DPR 2.25；WebView 153.0.8010.36。使用现有数据，首页 55 张卡片，其中 34 张封面尚在懒加载边界之外。临时以同签名 release 诊断包记录 WebView trace，最后替换为非 debuggable 的正式 release 包；安装使用 `adb install -r`。

新发现：这些尚未开始请求的封面也在持续运行 `background-position` 骨架动画。即使横向滚动容器把它们裁掉，动画仍引发大量样式和绘制工作。

修复：骨架默认标记 `is-deferred`，保留原尺寸、渐变和排版；已有 IntersectionObserver 真正触发图片请求时才启动原有扫光。成功、失败、重试、超时和 480px 预加载范围都沿用原逻辑，没有新增逐帧可见性计算或观察器。新增测试覆盖懒加载前静态、加载中动画、失败重试入口及切换档案后复位。

### A/B 结果

同一诊断 APK、同一首页，在 DevTools 临时覆盖 `.is-deferred` 的 animation，分别恢复旧行为和启用新行为，以排除后端、缓存及包版本差异。每组执行 6 次 `input swipe 1450 900 1450 1800 700`，结束后留 600ms 收尾；PerformanceObserver 和 rAF 在停止 trace、下载 trace 前终止，避免把传输耗时算入采样。

| 指标 | 强制恢复旧骨架动画 | 启用延迟骨架动画 |
| --- | --- | --- |
| 采样帧跨度 | 5250ms | 5100ms |
| Paint 事件数 | 7183 | 1198 |
| Paint 事件累计耗时 | 1743.04ms | 261.15ms |
| UpdateLayoutTree 累计耗时 | 343.14ms | 144.65ms |
| PrePaint 累计耗时 | 172.49ms | 76.26ms |
| rAF 帧间隔 P95 | 16.8ms | 16.7ms |
| 超过 50ms 的 longtask | 0 | 0 |

Paint 累计耗时约减少 85%，是专项绘制负担的改善，**不是整个应用快 85%**。设备会动态切换刷新率，不能根据单组 rAF 中位数推断固定刷新率提升。其他采样重复确认：实际编译包过滚的 Paint 累计耗时约 401ms；首次旧行为采样约 1865ms。

普通往返滚动的首次对比为 Paint 1919.34ms → 288.56ms。最终导航点击测试在首页和设置之间往返 6 次，12 次 click 的事件时长 P95 为 48ms；仍记录到 2 个 longtask，最长 84ms。它是固定场景的样本，不能当成全应用 INP，也不能据此判断所有页面的输入卡顿已经消失。横向拖动后图片数从 21 增至 24、延迟骨架从 34 降至 31，验证新封面仍按原预加载路径加载。

未保留的尝试：把渐变移到 transform 伪元素上能减轻部分绘制成本，但样式/PrePaint 成本增加，仍保留数千个 Paint 事件，因此没有加入源代码。最终仅保留“未开始加载就不运行动画”的较小改动。

复测时通过诊断 release 包的 WebView DevTools 连接采集 `devtools.timeline`；用 Android 原生输入注入上述固定手势，分别比较 trace 的 Paint/UpdateLayoutTree/PrePaint，以及 PerformanceObserver 的 event/longtask。原始 trace 和截图只保存在本机忽略文件中，不进入仓库，报告不包含服务器地址、设备序列号、档案标题或标识。

## 横向过滚、启动与缓存页补充

本轮在同一 Android 16 真机、同一 WebView 和现有应用数据下测量。冷启动指强制停止应用后重新启动进程，保留磁盘缓存和页面快照，不代表设备冷重启或首次安装。每版采样三次，使用 buffered longtask observer，采样到连接诊断后约 3.5 秒。

| 指标 | 修改前，三个样本 | 最终布局，三个样本 |
| --- | --- | --- |
| 长任务累计耗时 | 800 / 763 / 727ms | 682 / 676 / 656ms |
| 长任务数 | 6 / 5 / 5 | 4 / 4 / 4 |
| 最长长任务 | 352 / 341 / 330ms | 359 / 322 / 349ms |
| FCP | 1016 / 1084 / 1000ms | 1020 / 1016 / 1040ms |

长任务累计耗时中位数减少约 11%，首屏显示时间没有明确改善，最大的启动长任务仍然存在。不能把这次改动描述为消除了冷启动卡顿。CPU 采样发现，缩略卡片标签逐个读取隐藏副本的 offsetWidth 占约 160ms；仅调整预热调度没有改善首屏，最终又把缩略卡片改为原生两行换行。标签顺序、翻译、颜色、20px 胶囊与 48px 槽位保留，删除这些卡片的隐藏测量副本和标签 ResizeObserver。其他需要均衡瀑布排版的列表继续使用原测量路径。尝试过的 CSS layout containment 没有证明有效，没有保留。

预热仍串行、限量，先加载常用页面代码，再处理书架快照，避免收藏夹的网络读取挡住后面的代码预热。新增 idle 调度，字体加载、按住指针、滚动、滚轮或键盘输入期间让出执行机会；后台暂停，恢复前台后继续。预热不挂载所有页面、不请求全部封面，也不提高数据同步频率。

缓存页现在复用稳定的路由元素和各自的 LocationContext。只 memo 组件不够：React Router 的 Routes 即使传入固定 location，依然订阅外层位置变化，连带隐藏页面的 useLocation 消费者重渲染。专项计数测试验证：隐藏页在两个其他页面之间切换时不增加渲染；重新激活仍收到 active 上下文，查询参数、详情返回和滚动恢复继续生效。首页超过 90 秒的有效快照也用于首帧，再按原逻辑重新验证服务器、历史和档案存在性，失效广播仍会删除快照。

导航固定采样为首页/设置往返六次。click 事件时长 P95 从 56ms 到 48ms；长任务数从 2 到 3，最长从 54ms 到 65ms，说明单组端到端结果仍有波动，不能据此声称全部切页稳定提速。可确定消除的是上述隐藏页面的无关重渲染。回归测试另发现编辑页代码未加载时骨架返回按钮不可用，现已接入与正式编辑页相同的返回导航，在 chunk 仍挂起时也能返回。

横向过滚移动 scrollport 内的一层轨道，滚动容器自身不移动，封面、正文和阅读进度条仍处在同一个卡片缩放层。到边界才接管横向拖动；支持一次连续手势滚到边界后继续拉动、鼠标拖动与滚轮边界反馈，360ms 回弹并尊重 reduced-motion。真机注入 144px 左/右拖动，轨道分别偏移约 +35.4 / -35.4px，松手后清零；容器横坐标与页面 scrollTop 不变。纵向在卡片上拖动时页面正常滚动约 299px，轨道不偏移。边界滚轮也产生约 35.4px 阻尼位移并清零，没有链给页面。

回归覆盖：左右边界、方向判断、连续到边、逐帧合并、多指取消、卸载清理、预热输入退让与后台暂停、缓存路由渲染预算、冷编辑页返回、原生标签测量预算，以及现有首页/书架/档案库详情归属、搜索参数与滚动恢复测试。Android 构建同时执行 TypeScript、Vite、原生运行库依赖和构建戳检查。

最终验证：175 个测试文件、1875 项测试全部通过；前端和 Android release 构建通过。正式包关闭诊断调试，通过同签名覆盖安装保留应用数据。

## 阅读器手势与处理产物切换补充

同一 Android 16 设备、WebView 153、同一阅读页，比较原图和本地 Real-CUGAN 2× 产物（1426×2048 → 2852×4096）。每组执行六轮双指放大后缩小到弹性下限的手势，松手 220ms 后读取实际显示倍率；采样在 trace 传输前停止。修改前，已显示超分产物的一组有一轮仍停在 0.88 倍，同时记录到 152ms 长任务、150ms 最大帧间隔。trace 中包含浏览器任务与图形工作，不能把它全部归因于 JavaScript。

发现并复现的独立错误是：处理产物解码完成后会卸载原来的图片节点；触摸序列仍属于原节点，后续 touchend 无法冒泡到阅读器，导致缩小后不回弹。回归测试先在旧实现失败，再验证新实现保留触摸目标。现在只延迟显示层的候选图片创建、解码和提升：手势结束并留出回弹/翻页的安静窗口后才换图，不取消推理，不更改处理模型、进度与产物释放协议。已经开始解码的异步结果也用同步 busy 引用阻止竞态提升。

缩放变换按 rAF 合并，滚轮不再每次输入都提交 React 状态；细粒度放大滚轮不再被 100% 吸附阈值反复吞掉。回弹使用最后已写入的变换作为显式动画起点，避免忙碌提交合并 CSS 起止帧而瞬间归位；重复取消事件不会中断正在回弹的动画。触摸的隐式 pointer capture 释放也不再误取消另一根手指的平移，失焦/进入后台仍会清理手势。双指平移时不再提升整条三页轨道，只变换实际缩放层。

| 真机复测场景 | 松手 220ms 后回到 1× | >50ms 长任务 | rAF P95 / 最大间隔 |
| --- | --- | --- | --- |
| 原图，六轮 | 6/6 | 0 | 16.7 / 33.4ms |
| 超分进行中，六轮 | 6/6 | 0 | 16.8 / 16.8ms |
| 超分产物已显示，六轮 | 6/6 | 0 | 16.7 / 16.8ms |
| 超分产物已显示，再六轮 | 6/6 | 0 | 16.7 / 16.8ms |

样本支持此次手势复位修复和固定场景下的流畅度验证，不能推断所有设备的 GPU 卡顿都已消除，也不能将单次旧版长任务消失换算成全局提速比例。设备未配置可用 DLSSNR，未做真实 DLSSNR 或 Windows/iOS 硬件性能比较；两类产物共用的前端切换路径由回归测试覆盖。

新增五项测试覆盖手势中产物到达、已开始解码的竞态、显式回弹/重复取消/新手势打断、剩余手指继续操作与滚轮提交预算（40 次输入最多三次 React 提交）。最终完整测试 176 个文件、1880 项通过，前端构建通过；随后再次运行阅读器专项 126 项通过。原始 trace 仅存本机忽略目录，不提交档案内容、地址或设备标识。

最后重新打包非 debuggable release，通过 ARM64 运行库依赖闭包和构建戳校验，同签名覆盖安装保留数据；确认应用进程运行、屏幕有内容，并移除诊断端口转发。
